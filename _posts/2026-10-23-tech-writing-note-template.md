## 01. 기록의 목적

기술 문서는 *무엇을 했는지*만 나열하기보다, **왜 시작했고 어떻게 확인했는지**를 함께 남기면 나중에도 활용하기 좋습니다. 한 줄 요약, 실행 환경, 재현 방법, 결과를 같은 순서로 기록해 보세요.

- **목적** — 해결하려는 문제와 기대하는 결과
- **환경** — 운영체제와 관련 도구 버전
- **과정** — 시도한 방법과 선택의 이유
- **회고** — 결과, 한계, 다음 작업

## 02. 환경과 실행 예시

시작하기 전에 폴더 구조와 실행 조건을 명확히 적습니다. 아래 명령어는 **문서 작성 연습용 예시**입니다.

```bash
# 예시 Markdown 문서 작성
mkdir -p notes/images
printf '# 첫 번째 학습 기록\n' > notes/README.md
ls -R notes
```

### 실행 내용을 기록하는 기준

버전은 `v1.0`, 실행 경로는 `notes/`처럼 짧은 인라인 코드로 표시합니다. 명령어가 긴 경우에는 아래처럼 언어를 명시한 코드 블록을 사용합니다.

```python
from pathlib import Path

root = Path("notes")
print("문서 수:", len(list(root.glob("*.md"))))
```

같은 작업이라도 환경에 따라 결과가 달라지므로, 중요한 버전과 경로를 같이 기록합니다.

| 항목 | 기록 내용 |
| --- | --- |
| 운영체제 | 본인이 사용한 OS 기재 |
| 도구 | 언어 / 프레임워크 버전 |
| 결과물 | 저장소·문서·이미지 경로 |

## 04. 회고와 다음 단계

기록 마지막에는 다음에 시도할 내용이나 수정할 부분을 남깁니다. 게시글이 길어져도 핵심만 정돈하면 읽는 데 방해가 되지 않습니다.

> 작성할 때의 기준: 처음 보는 사람이 맥락을 이해할 수 있는가? 몇 주 뒤의 내가 다시 실행할 수 있는가?
